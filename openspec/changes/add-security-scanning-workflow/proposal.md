## Why

The repository has no automated vulnerability scan. A local `npm audit` currently reports 23 advisories, including two high-severity findings, and CodeQL is not enabled, so newly disclosed issues can sit unnoticed until a maintainer happens to run the audit. The project is a public, zero-runtime-dependency library, which means GitHub-hosted runners, Dependabot, and CodeQL are all available at no cost. The missing piece is a scheduled automation that finds fixable dependency issues and turns them into reviewable PRs.

## What Changes

This change is **additive and non-breaking**. It adds CI automation and maintainer documentation; the component API and published package keep their current behavior, and existing workflow jobs keep theirs except for one additive test step in `ci.yml` and the narrowly guarded auto-merge path for security-audit PRs.

- Add a scheduled dependency audit workflow (`.github/workflows/security-audit.yml`) that:
  - runs daily on `master` and on demand via `workflow_dispatch`;
  - records the `npm audit` baseline and applies non-breaking fixes with `npm audit fix` (never `--force`);
  - opens or updates one PR on a deterministic branch (`security/npm-audit-fix`) when `package.json` or `package-lock.json` changes;
  - dispatches the existing CI workflow on the automation branch because GitHub does not trigger `pull_request` workflows for PRs created with `GITHUB_TOKEN`, then signals auto-merge with a `repository_dispatch` event after that CI run succeeds;
  - puts before/after finding counts, fixed advisories, and remaining unfixable advisories in the PR body and job summary;
  - fails the run only when production (`--omit=dev`) vulnerabilities remain, so dev-only noise does not fail the schedule every day.
- Add a dependency-free report helper (`scripts/security-audit.js`) with `node:test` coverage, so severity counts, fixed/remaining advisories, and the PR body are generated by tested code instead of untested inline shell; run its tests with one additive step in `ci.yml`.
- Extend `.github/workflows/dependabot-auto-merge.yml` to also auto-merge the audit PR, but only when CI succeeded, the PR is the known automation branch authored by `github-actions[bot]`, its head is this repository (not a fork), and its diff is limited to dependency manifests.
- Add a CodeQL workflow (`.github/workflows/codeql.yml`) for JavaScript/TypeScript with `build-mode: none`, running on pushes and PRs to `master` plus a weekly schedule, uploading results to GitHub code scanning.
- Perform a one-time remediation of the findings that `npm audit fix` cannot resolve: widen the exact `brace-expansion` override in `package.json` to a patched 5.x range and refresh `package-lock.json`.
- Update `CONTRIBUTING.md` to document the scan, the PR it creates, the merge policy, and the manual path for findings that need a major upgrade.

**Explicitly out of scope:** paid scanning services, third-party security bots, automatic source-code fixes, automatic major dependency upgrades, Dependabot security-update repository settings, secret scanning, SBOM generation, and runtime/dependency changes to the published package.

## Capabilities

### New Capabilities

- `security-scanning`: scheduled dependency vulnerability scanning, automated fix-PR creation and idempotency, unfixable-finding reporting, guarded auto-merge of audit PRs, and CodeQL code scanning for the repository.

### Modified Capabilities

None. `openspec/specs/` has no existing capability specs.

## Impact

- **Workflows:** new `security-audit.yml` and `codeql.yml`; guarded changes to `dependabot-auto-merge.yml` (trigger branches, `repository_dispatch` handoff, and author/diff/SHA checks); one additive `workflow_dispatch` trigger for `ci.yml` so the audit can request validation for its own PR, plus one additive test step in `ci.yml` for the report helper. No changes to `release.yml` or `publish.yml`.
- **Repository settings:** code scanning requires the Actions permission to upload security events (`security-events: write`); the public repository is already eligible for free CodeQL. The audit workflow uses `actions: write` to dispatch the CI validation run. Auto-merge requires the repository "Allow auto-merge" setting already documented in `RELEASE.md`.
- **Dependencies:** no runtime or peer dependency changes. Dev dependency resolutions move within existing semver ranges, plus the `brace-expansion` override range bump.
- **Scripts/tests:** new `scripts/security-audit.js` and `scripts/security-audit.test.js`; `package.json` gains a `test:security-audit` script. The published package excludes `scripts/`, so its contents do not change.
- **Package output:** unchanged; the published bundle, types, and entry points are untouched.
- **Cost and secrets:** no paid services and no new secrets. Workflows authenticate with the built-in `GITHUB_TOKEN` and official GitHub actions only.
- **Docs:** `CONTRIBUTING.md` dependency-update section gains the scan and merge policy; consumer-facing `readme.md` is unchanged because there is no API change.
